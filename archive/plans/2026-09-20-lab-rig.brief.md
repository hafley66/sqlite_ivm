## Mint both labs first

```bash
./labs/new-lab.sh the-gang-builds-a-wider-table
./labs/new-lab.sh the-gang-finds-out-where-the-time-went
```

The script computes datestamp and index; never hand-name a directory. Each lab is ISO:
its own `[workspace]`, no path dependency on the entry point, shared crates pinned to
the versions the root manifest resolves. Leave that shape alone.

## Task 1: the rig

The generator every later lab measures against. Axes:

| axis | values |
|---|---|
| N source tables | 2, 4, 8 |
| M columns per table | **10 and 20** |
| J join arity | 2, 3, 4 |
| seed | fixed, and the seed is an input |

No four-column tests. Width is the point.

Two requirements that are easy to skip and expensive to retrofit:

**Spans must be assertable.** `hafley-observe` already ships `CountRecorder`,
`SpanCounts::assert_children_at_most`, and `assert_growth`. Name spans stably and key
the rig's own assertions off them, because every later lab inherits this instrument.
A rename later breaks labs that are not written yet.

**Pin the log filter.** `hafley-observe/src/1_format.rs:33` falls back to `trace` when
nothing is set, by deliberate design for a CLI. In a fold that emits a span per row that
makes the logger the thing you are measuring. The rig sets `HAFLEY_LOG` explicitly and
never inherits it.

Test plan is in the issue's `## Test Plan`. Six cases, each with a stated reason.
The rig's correctness is under test; the engine's is not. That belongs to `tests/**`,
which you do not own.

## Task 2: the profile

Where the time actually goes, per single source-row change, at M=20. The nine steps
and their sites are listed in `docs/2026-09-19-vtab-clocks.md` under
"What is nailed to which clock today". Every one of them is on the row clock today.

Report percent of wall time per step. Then run the same fold with the subscriber on and
off and report the delta, because of the `trace` default above. That delta can invalidate
the whole profile, so it is measured, never assumed.

Assert on ratios and rankings only. Never on absolute timings; they are machine-specific
and would fail the suite on a different laptop. Absolute numbers go in
`HYPOTHESIS.md` under `## Verdict`, dated.

**The prior to test, not inherit.** An earlier measurement on a different engine fold
put SQLite at 11.9% of wall time and application-side Rust re-scanning at 88%. If that
shape holds here, the SQL-side labs are noise. That outcome is a success for this lab.

Output is a ranking of labs 3 through 9 by measured upside. That ranking unblocks the
epic `lab-queue-round-one`.

## Validate

Each lab is its own workspace:

```bash
cd labs/<lab-dir> && cargo test
```

Do not run the root battery. You own no root code. If the root battery breaks, it was
not you, and `.github/CI-KNOWN-RED.md` lists the legs allowed to be red.

Measure a leg three times, never once, and never under lane load.

## The 10-second law

Any single operation over 10s is a defect to investigate now. Batteries run in the
background with a per-test cap. Nothing you write may seize the machine; a change that
can beachball it is a blocking defect. If the rig at N=8, M=20, J=4 takes minutes, that
is a finding to report, not a thing to wait through.

## Style laws

- Comment budget: only constraints the code cannot show. No change-log narrative,
  no dates, no arc references.
- `eprintln!` never in `src/**`. `tracing` only.
- Every loop and every recursion carries an explicit budget and a named diagnostic
  when the budget is hit. The bound is a constant with a comment saying what it protects.
- Colocated consistency: inside a file, follow that file's style.
- No em dashes. Banned words in prose and identifiers: provenance, substrate,
  load-bearing, regime, "ground truth" (say oracle), refusal.
- "support" is banned, use refCount.
- Build-vs-buy: no bespoke queue, scheduler, parser, retry, or cache without a written
  candidate table first.

## Receipts

Close checkboxes with `issuectl check <slug> "<substring>"`. Never hand-edit
frontmatter. Record commits with a `Refs-Issue: @<slug>` trailer.

Report: `git log --oneline`, `git status`, `git diff --stat origin/main...HEAD` showing
only owned files, the per-step percent table, and the subscriber on-vs-off delta.

`rc=0` proves nothing. Grade your own tree before you say it is done.
