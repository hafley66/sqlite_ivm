## Task 1: dylib-entrypoint-untested

Every test in `tests/*.rs` calls `register(&db)` directly, which links the Rust in and
never reaches `sqlite3_extension_init` at `src/3_extension.rs:84`. Rename that symbol
today and the whole battery stays green while the shipped artifact is dead.

`rusqlite/load_extension` is already an optional feature, wired to `bench`
(`Cargo.toml:20`). Reuse it; do not add a new feature.

Build the artifact with `bash scripts/0_build.sh`, which prints the platform path and
already handles dylib / so / dll.

Acceptance criteria are in the issue. The test plan is in its `## Test Plan` section
and is the contract: four cases, each with a stated reason. Do not add cases without
adding the reason.

The one thing the plan forbids: no memory budget on these tests. A `dlopen`'d library
resolves its own allocator symbols, so a counting allocator in the test process would
report a number that means nothing.

## Task 2: lab-session-probe

An ISO lab. Mint it:

```bash
./labs/new-lab.sh the-gang-compiles-a-flag-they-never-needed
```

The script computes the datestamp and index. Never hand-name the directory. It seeds a
`Cargo.toml` with its own `[workspace]` and no path dependency on the entry point, with
shared crates pinned to the versions the root manifest resolves. Leave that shape alone.

Four gates, each a yes or no with the probe that answered it:

1. does `rusqlite` build with the `session` feature on this toolchain, and does
   `SQLITE_ENABLE_SESSION` also require `SQLITE_ENABLE_PREUPDATE_HOOK`
2. does a session record a table with no declared `PRIMARY KEY`
3. does a session see writes that arrived through a virtual table's `xUpdate`
4. does a changeset coalesce three statements into one entry, and does a patchset
   strip old values while a changeset keeps them

Gate 3 is the one that matters most. Every maintenance write in this repo goes through
`xUpdate` (`src/2_vtab.rs:386`). If sessions cannot see those, a later arc is dead and
you have saved a week.

A failing gate is a passing lab. Write the answer in `HYPOTHESIS.md` under `## Verdict`
with the date. Do not try to make a gate pass.

## Style laws

- Comment budget: only constraints the code cannot show. No change-log narrative,
  no dates, no arc references.
- `eprintln!` never in `src/**`. `tracing` only.
- Every loop and every recursion carries an explicit budget and a named diagnostic
  when the budget is hit. The bound is a constant with a comment saying what it protects.
- Colocated consistency: inside a file, follow that file's style.
- No em dashes. Banned words in prose and identifiers: provenance, substrate,
  load-bearing, regime, "ground truth" (say oracle), refusal.
- dl8 vocabulary: products and rows, never "rel". "support" is banned, use refCount.
- A compiler error for an unbuilt construct is "not built yet" with the throw site
  cited. Never report it as a language limit.
