00 / THE SQL BEING MEASURED

Count facts and sum amount × factor, per group

SELECT
    f.group_id,
    COUNT(*) AS n,
    SUM(f.amount * d.factor) AS s
FROM fact AS f
JOIN dimension AS d
    ON f.group_id = d.group_id
GROUP BY f.group_id;

n counts matched fact rows. s adds each fact’s amount multiplied by its matching dimension factor. One dimension row exists per group_id.

Target fixture: 12,000 initial fact rows, 110 dimension groups, 1,000-row mutation batches. Group 0 has 200 facts, so changing its single dimension factor changes 200 join contributions.

Tables and durability

PRAGMA trusted_schema = ON;
PRAGMA recursive_triggers = ON;
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL;

CREATE TABLE fact (
    id       INTEGER PRIMARY KEY,
    group_id INTEGER NOT NULL,
    amount   INTEGER NOT NULL
);

CREATE TABLE dimension (
    group_id INTEGER PRIMARY KEY,
    factor   INTEGER NOT NULL
);

Install the maintained query

The adapter loads the native extension, loads the initial rows in a transaction, then calls:

SELECT sqlite_ivm_create(
    'summary',
    'SELECT f.group_id,COUNT(*) AS n,SUM(f.amount*d.factor) AS s FROM fact f JOIN dimension d ON f.group_id=d.group_id GROUP BY f.group_id'
);

Why the historical lab uses JSON keys

Its delta and result tables declare key TEXT PRIMARY KEY. JSON arrays encode [side,k,v] for staged deltas and [group_key] for grouped results, supplying one target for ON CONFLICT(key). A NULL element still produces a non-NULL text key.

The same implementation joins native k columns through source indexes, groups signed contributions, and adds directly to result accumulators. Current join/group keys occupy separate native columns and match NULL groups with IS.
