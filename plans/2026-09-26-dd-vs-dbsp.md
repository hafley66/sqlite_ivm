# Differential Dataflow 0.25.1 and Feldera DBSP code comparison

Scope: Differential Dataflow (DD) implementation in `labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs`, against the installed `differential-dataflow-0.25.1` source, and Feldera DBSP in `~/projects/ext/feldera/crates/dbsp`. Statements below refer to those source trees.

The current worktree has no `crates/ivm-engine`; the `Rel` trait available for the requested method mapping is the lab's `src/1_rel.rs` (lines 52–74). The mapping uses that trait and its DD implementation.

| Area | Differential Dataflow 0.25.1 | Feldera DBSP |
|---|---|---|
| Join, incremental bilinear form | The lab maps each row to `(join_key, row)` on both sides, calls collection `join`, then concatenates rows (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:153-170`). The collection API arranges both inputs and calls `join_core` (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/collection.rs:1128-1160`); the trace join multiplies input differences and emits the result (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/operators/arrange/arrangement.rs:245-260`). | Indexed streams join on a shared key and a closure produces each output value (`~/projects/ext/feldera/crates/dbsp/src/operator/join.rs:108-142`). | Recursion / fixpoint | The DD implementation opens a nested scope, creates one `Variable` per recursive relation, lowers each body against those variables, thresholds the result, and sets each variable (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:57-92`). DD `iterate` circulates differences until convergence and requires consolidation where canceling records could otherwise circulate (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/operators/iterate.rs:1-15, 81-99`). | `recursive` builds a typed nested circuit and calls the dynamic recursive operator (`~/projects/ext/feldera/crates/dbsp/src/operator/recursive.rs:228-238`). | Aggregation, including min/max retraction | `Count` and `Sum` encode accumulators in the record difference and reduce to one group output (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:249-275`). `Min` and `Max` first threshold live rows, hash values into 16-way buckets, reduce extrema through 16 levels, and emit the resulting extrema (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:277-325`). Thus removal of the selected extremum reveals the next live value through recomputation over the reduced live input (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:284-312, 316-325`). | Incremental aggregation constructs an incremental aggregate operator from a user `Aggregator` (`~/projects/ext/feldera/crates/dbsp/src/operator/aggregate.rs:26-57`). `Min` sums each key's weights, skips keys with zero net weight, and returns the first nonzero key (`~/projects/ext/feldera/crates/dbsp/src/operator/dynamic/aggregate/min.rs:31-70`). On each affected key, the incremental implementation recomputes from the input trace and retracts prior values through its output trace (`~/projects/ext/feldera/crates/dbsp/src/operator/dynamic/aggregate.rs:764-794, 868-930`). |
| State storage, arrangement / trace vs spine | Arrangement holds a stream of indexed batches and a trace of accumulated batches; traces merge batches and can compact logical times (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/operators/arrange/mod.rs:1-40`). The lab's chosen default key trace is `TraceAgent<KeySpine<Row, Time, W>>` (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:5-12, 27-29`). The fueled spine stores merging batches and pending batches, then applies incremental merge effort (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/trace/implementations/spine_fueled.rs:79-98`). | `Stream::trace` records each untimed input batch at the current timestamp into a timed trace (`~/projects/ext/feldera/crates/dbsp/src/operator/trace.rs:24-35`). DBSP's `Spine` uses an asynchronous merger over immutable batches (`~/projects/ext/feldera/crates/dbsp/src/trace/spine_async.rs:1444-1475`). |
| Spill to disk | The lab selects `KeySpine` over `VecCollection` (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:8-12, 27-29`); this selected ordered-list spine stores batches and in-progress merges (`~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/trace/implementations/ord_neu.rs:11-35`; `~/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/differential-dataflow-0.25.1/src/trace/implementations/spine_fueled.rs:79-98`). That path is not selected by this lab implementation. | DBSP can send batches to configured storage based on size thresholds and memory pressure. Runtime exposes separate thresholds for merge output, foreground spine inserts, and transient step batches (`~/projects/ext/feldera/crates/dbsp/src/circuit/runtime.rs:1117-1204`). `Spine::maybe_flush_batch` writes a memory batch into storage when the configured threshold or high memory pressure selects storage (`~/projects/ext/feldera/crates/dbsp/src/trace/spine_async.rs:2123-2173`). |
| Time model | The lab uses `u64` outer time and `Product<u64,u64>` inner loop time; its `Nest` trait requires timely `Timestamp` and DD `Lattice` (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/2_dd.rs:27-40`). | Operator construction cost | The lab lowers each IR node once using a node-indexed memo table (`labs/20260924.0.the-gang-runs-a-program-as-data-through-differential-dataflow/src/1_rel.rs:126-184`).
